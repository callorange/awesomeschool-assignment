# Proposal

## Why

현재 신청은 저장·접수만 가능하고 관리자가 상담 경과를 기록하거나 재연락 대상을 찾을 수 없다. Django 기본 admin에서 신청을 보존하며 수정 이력과 상담 진행을 추적하고, 기존 미등록 교육·안내 모델도 관리할 수 있게 한다.

## What Changes

- Django 기본 admin에 교육·신청·상담 기록·자동 안내·발송 시도·공유 전송 예산을 등록한다. 내부 안내 처리 데이터는 조회 전용으로 제공한다.
- 신청 상태를 접수·상담중·재연락 예정·완료·취소로 구분한다. 취소는 상담 후 진행하지 않기로 확정한 경우 관리자가 사유와 함께 처리하며 사용자 취소 화면은 만들지 않는다.
- 최초 연락 가능 날짜와 별도로 다음 연락 예정 일시를 관리하고 오늘·기한 경과·일정 미정인 재연락 대상을 조회한다.
- 상담 기록은 작성자·작성 시각·연락 결과·내용·당시 다음 연락 예정 일시를 누적하며 정정도 새 기록으로 남긴다.
- 신청과 상담 기록은 삭제하지 않는다. 과제 원문의 물리 삭제 요구 대신 데이터 보존 정책을 채택한 차이를 README에 설명하며 보관·복구 기능은 추가하지 않는다.
- `django-simple-history`로 신청 변경 전후 값·변경자·시각을 조회한다. 이력 복원·편집·삭제는 제공하지 않는다.
- 신청 수정 뒤에도 최초 제출 비교와 공개 접수 응답을 보존하고, 미처리 안내와 수정·종료 상태의 정합성을 유지한다.
- MVP 이후 후보는 별도 관리자 UI, 담당자 배정, 자동 재연락 알림·캘린더 연동, Spreadsheet 내보내기다. 이번 범위에는 포함하지 않는다.

## Capabilities

### New Capabilities

- `application-management`: 관리자 권한, 신청 조회·수정·보존, 상담 상태·누적 기록·재연락 일정·변경 이력, 안내 기록 조회.
- `education-administration`: 기본 admin에서 교육 콘텐츠와 접수 활성 여부 등록·수정, 기존 검증과 이미지 정리 계약 유지.

### Modified Capabilities

- `education-applications`: 변경 가능한 관리 데이터와 최초 제출 비교를 분리하고 관리 상태 변경 뒤에도 공개 접수 확인 계약 유지.
- `application-notifications`: 신청 정보 정정과 완료·취소에 따른 미처리 안내 조정, 발송 중 변경 제한, 재연락 일정과 안내 분리.

## Impact

- `src/education/models.py`, `admin.py`, `serializers.py`, `api.py`, 안내 task와 지원 모듈, 관련 테스트와 신규 migration이 구현 대상이다.
- `pyproject.toml`·`uv.lock` 공통 의존성과 공통 Django 설정에 `django-simple-history`를 추가한다. 현재 Python 3.14·Django 6.1 조합을 명시적으로 지원하는 3.13 계열을 기준으로 검증한다.
- 기존 신청을 지우거나 과거 migration을 재작성하지 않고 최초 제출 snapshot·초기 변경 이력을 보완한다. 과거 변경자·변경 내역을 추정하지 않는다.
- 공개 URL·입력 필드·CSRF·개인정보 비공개 경계는 유지한다. admin의 새 개인정보 조회 권한과 기록 보존을 검증한다.
- README·아키텍처·기능 검증·운영 가이드를 최종 구현과 동기화한다. 과제 원문과 managed 규칙은 수정하지 않는다.
