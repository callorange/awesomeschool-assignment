# Spec Delta

## Purpose

권한 있는 관리자가 기본 관리자 화면에서 교육 소개 콘텐츠와 상담 접수 여부를 유지하게 한다. 기존 교육 입력 검증과 미디어 보존 규칙을 적용하고, 교육 정보 변경으로 이미 접수된 신청의 내용이 바뀌지 않게 한다.

## ADDED Requirements

### Requirement: 교육 등록과 수정

시스템은 교육 조회·등록·변경 권한에 따라 교육명·URL 식별자·소개·대표 이미지·대체 텍스트·목표·대상·커리큘럼·운영 정보·접수 활성 여부를 기본 관리자 화면에서 관리하게 해야 한다(SHALL). 목록에는 교육명·URL 식별자·운영 방식·접수 여부를 표시하고 검색·필터를 제공해야 한다(SHALL).

#### Scenario: 교육 등록과 접수 중단
- **WHEN** 권한 있는 관리자가 교육을 등록하거나 접수를 중단한다
- **THEN** 공개 교육 화면에 저장 결과가 반영되고 접수 중단 교육의 소개는 유지하며 새 신청만 거부한다

#### Scenario: 권한 없는 수정 요청
- **WHEN** 조회 권한만 가진 사용자가 교육 변경을 직접 POST한다
- **THEN** 변경을 거부하고 기존 콘텐츠를 유지한다

### Requirement: 교육 입력 검증과 신청 당시 정보 유지

시스템은 기존 목표·대상·커리큘럼 구조 및 교시 순서 검증을 관리자 입력에도 적용해야 한다(SHALL). 고유 미디어 식별자는 수정할 수 없어야 하며 교육명·URL 식별자 수정이 기존 신청 당시 교육 정보와 최초 제출 확인을 바꾸지 않아야 한다(SHALL).

#### Scenario: 잘못된 커리큘럼 입력
- **WHEN** 관리자가 잘못된 자료 구조나 교시 순서의 커리큘럼을 저장한다
- **THEN** 필드 오류로 알리고 잘못된 값을 저장하지 않는다

#### Scenario: 교육명과 URL 식별자 변경
- **WHEN** 기존 신청이 있는 교육의 이름과 URL 식별자를 수정한다
- **THEN** 공개 소개에는 새 값이 표시되며 기존 신청과 안내에는 신청 당시 교육명이 유지된다

### Requirement: 교육 이미지 변경의 기존 보호 유지

시스템은 관리자 화면의 이미지 교체에도 기존 transaction·비동기 미참조 파일 정리 규칙을 유지해야 한다(SHALL). 이번 화면은 교육 개별·일괄 삭제 기능을 제공하지 않아야 한다(SHALL). 기존 프로그램 경로에서 교육이 삭제돼도 신청과 상담 기록을 보존해야 한다(SHALL).

#### Scenario: 대표 이미지 교체
- **WHEN** 교육 이미지를 교체하고 저장을 확정하거나 취소한다
- **THEN** 확정 후 현재 참조·공유 파일을 보호하며 미참조 이전 파일만 정리하고 취소 시 기존 데이터와 이미지를 유지한다

#### Scenario: 교육 삭제 경로와 신청 보존
- **WHEN** 관리자 화면으로 교육 삭제를 요청하거나 기존 프로그램 경로에서 교육을 삭제한다
- **THEN** 관리자 삭제는 거부하고 프로그램 삭제 시에도 신청·상담은 남으며 원본 교육 연결만 해제된다
