# Proposal

## Why

현재 Education은 교육 소개를 제공하지만 운영 방식과 상담 접수 가능 여부를 구분하지 못하고, 콘텐츠 구조 검증이 초기화 명령에만 있다. 교육 신청을 상담 후 진행 조건을 협의하는 접수로 해석하여, 향후 편집과 신청 기능이 사용할 최소한의 교육 데이터 계약을 먼저 마련한다.

## What Changes

- Education에 운영 방식(operation_type: instructor_led / courseware), 진행 안내(operation_note), 상담 접수 활성 여부(is_accepting_inquiries)를 추가한다.
- 기존 소개·이미지·목표·추천대상·시수별 커리큘럼·출처와 JSON 구조를 유지한다. 기수·반·좌석·일정·지역 제한 모델은 추가하지 않는다.
- 목표·추천대상·커리큘럼 검증을 모델 필드와 초기화 명령에서 재사용하여 향후 편집 입력에도 동일한 계약을 제공한다.
- 기존 교육과 미디어를 보존하는 migration을 제공하고 교육 3개의 프리셋에 새 운영 정보를 명시한다. 재초기화로 기존 운영 정보를 덮어쓰지 않는다.
- 상세 화면에 운영 방식·진행 안내·상담 접수 상태를 제공하되 신청 폼이나 동작하지 않는 신청 링크는 만들지 않는다.
- 범위 제외: 교육 편집 UI·admin 등록, 신청 모델·폼·API·접수 차단 처리, 자동 메일, 견적 계산, 라이선스 판매, 정원·요일반·기수 관리.
- 후속 MVP의 신청 CRUD·상태 관리·DRF GET/POST를 유지한다. 별도 관리자 화면·Spreadsheet 내보내기·AWS 배포 계획은 MVP 이후로 유지한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `education-catalog`: 교육 운영 정보와 모델 검증 계약을 추가하고 공개 상세에서 운영 정보·접수 상태를 안내한다.
- `education-presets`: 새 운영 정보를 포함한 초기 데이터를 제공하고 공통 검증·기존 운영 정보 보존을 보장한다.

## Impact

- 모델·migration·공통 validator, 초기화 명령·프리셋, 교육 상세 template와 필요한 생성 CSS, 모델·프리셋·페이지 테스트가 영향 범위다.
- README와 docs/architecture.md의 교육 데이터 설명을 구현 시 동기화한다. 과제 원문과 기존 archive는 수정하지 않는다.
- 공개 URL·기존 JSON 형태·미디어 참조는 유지한다. 새 의존성·외부 연결·개인정보 수집·권한 변경은 없다.
- 향후 신청 기능은 Education FK와 운영 방식·접수 상태를 사용한다. 이번 변경은 저장된 상태와 안내까지만 제공하며 실제 접수 검사는 후속 신청 기능의 책임이다.
