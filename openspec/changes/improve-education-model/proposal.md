# Proposal

## Why

교육 신청을 상담 후 진행 조건을 협의하는 접수로 해석하여, 향후 편집과 신청 기능이 사용할 최소한의 교육 데이터 계약을 마련한다. 기존 범위의 운영 정보·공통 검증 구현에 이어 이미지의 교육별 저장 경로와 삭제·교체 수명주기를 보완하여 파일 집중과 미참조 파일 잔존을 줄인다.

## What Changes

- Education에 운영 방식(operation_type: instructor_led / courseware), 진행 안내(operation_note), 상담 접수 활성 여부(is_accepting_inquiries)를 추가한다.
- 기존 소개·이미지·목표·추천대상·시수별 커리큘럼과 JSON 구조를 유지한다. 기수·반·좌석·일정·지역 제한 모델은 추가하지 않는다.
- 목표·추천대상·커리큘럼 검증을 모델 필드와 초기화 명령에서 재사용하여 향후 편집 입력에도 동일한 계약을 제공한다.
- 수집 기록 4개 필드는 모델과 상세에서 제거하고 프리셋 JSON에만 보관한다. 0001은 유지하고 후속 migration 파일은 삭제 후 Django로 단일 0002를 생성한다. 사용자 승인으로 로컬 DB 컨테이너·볼륨을 초기화하고 교육 3개의 프리셋에 새 운영 정보를 명시한다. 재초기화로 기존 운영 정보를 덮어쓰지 않는다.
- 상세 화면에 운영 방식·진행 안내·상담 접수 상태를 제공하되 신청 폼이나 동작하지 않는 신청 링크는 만들지 않는다.
- 신규 이미지 저장은 `education/<media_id의 32자 hex>/images/`로 나누고 프리셋에는 SHA256, 일반 파일 저장에는 UUID 파일명을 사용한다. 교육별 고정 media_id는 저장 전에 UUIDv7으로 생성하고 편집 입력에서 제외한다. 프리셋에는 고정 UUIDv7을 기록해 실패 재실행 시 키를 유지한다. 덮어쓰기 금지와 Storage가 반환한 실제 이름 저장을 유지한다.
- 교육 삭제 또는 이미지 교체가 commit되면 다른 교육이 참조하지 않는 이전 파일만 해당 Storage로 정리한다. rollback과 공유 참조에서는 보존하고, 정리 실패는 기록한다.
- 기존 이미지 경로와 파일은 일괄 이동하지 않는다. 프리셋 실패 시 파일 보존·재실행 재사용 정책은 유지한다. 파일 전수 검색·일괄 청소·정리 작업 큐는 범위에 포함하지 않는다.
- 범위 제외: 교육 편집 UI·admin 등록, 신청 모델·폼·API·접수 차단 처리, 자동 메일, 견적 계산, 라이선스 판매, 정원·요일반·기수 관리.
- 후속 MVP의 신청 CRUD·상태 관리·DRF GET/POST를 유지한다. 별도 관리자 화면·Spreadsheet 내보내기·AWS 배포 계획은 MVP 이후로 유지한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `education-catalog`: 교육 운영 정보와 모델 검증·공개 안내, 이미지 저장 및 삭제·교체 수명주기 계약을 제공한다.
- `education-presets`: 새 운영 정보와 교육별 이미지 경로를 제공하고 공통 검증·기존 운영 정보 보존·실패 복구를 보장한다.

## Impact

- 모델·migration·공통 validator, 초기화 명령·프리셋, 이미지 경로 함수·삭제/교체 signal 등록, 교육 상세 template와 필요한 생성 CSS, 관련 테스트가 영향 범위다.
- README와 docs/architecture.md의 교육 데이터 설명을 구현 시 동기화한다. 과제 원문과 기존 archive는 수정하지 않는다.
- 공개 URL·기존 JSON 형태·기존 미디어 참조는 유지하며 신규 이미지 키만 새 규칙을 사용한다. 새 의존성·개인정보 수집·권한 변경은 없다. 정리 정책 구현 후 운영 모드의 교육 삭제·이미지 교체는 해당 S3 파일 삭제를 수반할 수 있으나 실제 AWS 작업은 이번 개발·검증에서 실행하지 않는다.
- 향후 신청 기능은 Education FK와 운영 방식·접수 상태를 사용한다. 이번 변경은 저장된 상태와 안내까지만 제공하며 실제 접수 검사는 후속 신청 기능의 책임이다.
