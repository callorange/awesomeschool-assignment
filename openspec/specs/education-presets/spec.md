# education-presets Specification

## Purpose

평가자가 별도 콘텐츠 입력이나 원본 사이트 접근 없이 히어로스쿨 교육 3개로 초기 환경을 재현할 수 있게 한다. 초기 설정을 반복해도 기존 교육 데이터를 보존하며, 제공 데이터의 출처와 수집 시점을 확인할 수 있도록 한다.

## Requirements

### Requirement: 고정 교육 프리셋 제공
프로젝트는 프롬프트 히어로·감정탐험 히어로·관계 히어로의 교육명·한 줄 소개·이미지·목표·추천대상·시수별 커리큘럼을 포함하는 고정 프리셋을 제공해야 한다(SHALL). 원문 URL과 실제 수집일을 함께 기록하고, 요약·편집한 내용은 원문과 구별해야 한다(SHALL).

#### Scenario: 프리셋 내용 확인
- **WHEN** 평가자가 제공된 프리셋과 출처 기록을 확인한다
- **THEN** 정확히 지정된 교육 3개와 각 교육의 필수 소개 데이터·로컬 이미지·원문 URL·수집일을 확인할 수 있다

### Requirement: 명령 하나로 초기 교육 설정
시스템은 migration을 완료한 빈 DB에 명령 하나로 교육 3개와 이미지를 선택된 미디어 저장소에 저장하고 결과를 보고해야 한다(SHALL). 개발 모드에서는 원본 사이트·외부 API·AWS 자격 증명을 요구하지 않아야 한다(SHALL). 운영 모드에서는 준비된 S3에 명시적으로 저장해야 한다(SHALL).

#### Scenario: 새 평가 환경 초기화
- **WHEN** 평가자가 README의 개발 절차로 migration 후 초기 데이터 명령을 실행한다
- **THEN** 교육 3개가 영속 저장되고 이미지는 로컬 미디어에 복사되어 랜딩과 상세에서 조회되며 생성 건수가 출력된다

#### Scenario: 운영 저장소 초기화
- **WHEN** 운영 모드를 선택하고 준비된 S3에 초기 데이터 명령을 명시적으로 실행한다
- **THEN** 필요한 이미지가 해당 저장소에 저장되고 교육의 이미지 URL은 CloudFront를 사용하며 AWS 리소스는 자동 생성하지 않는다

### Requirement: 반복 설정 시 기존 데이터 보존
시스템은 초기 데이터 명령 재실행 시 이미 존재하는 교육과 연결 이미지를 덮어쓰거나 중복 생성하지 않아야 한다(SHALL). 프리셋 외의 기존 교육·파일·객체도 변경하거나 삭제하지 않아야 한다(SHALL).

#### Scenario: 수정된 교육을 보존하는 재실행
- **WHEN** 초기화한 교육의 소개를 변경하고 별도 교육을 추가한 후 명령을 다시 실행한다
- **THEN** 수정 내용·이미지 참조·이미지 파일과 별도 교육은 그대로 유지되고 프리셋 교육이 중복되지 않으며 생성·건너뛴 건수가 보고된다

#### Scenario: 일부 교육만 존재하는 환경
- **WHEN** 지정된 교육 중 일부만 존재하는 DB에서 명령을 실행한다
- **THEN** 없는 교육과 필요한 이미지만 추가되고 기존 교육·이미지는 유지된다

### Requirement: 잘못된 프리셋의 부분 저장 방지
시스템은 프리셋의 필수 데이터와 참조 이미지 원본을 쓰기 전에 검증해야 한다(SHALL). 입력·저장소·DB 오류는 원인을 식별할 수 있게 보고하고 해당 실행의 교육 데이터를 부분 저장하지 않아야 한다(SHALL). DB 롤백 후 파일이 남는 경우 이를 보고하고 기존 객체를 자동 삭제하지 않아야 한다(SHALL).

#### Scenario: 필수 정보 또는 로컬 이미지 누락
- **WHEN** 프리셋에 필수 소개 정보나 참조 이미지가 누락된 상태에서 초기 데이터 명령을 실행한다
- **THEN** 쓰기 전에 실패를 보고하고 해당 실행으로 교육이나 이미지를 저장하지 않는다

#### Scenario: 이미지 저장 도중 실패
- **WHEN** 일부 이미지 저장 후 저장소 오류 또는 DB 오류가 발생한다
- **THEN** 실패를 보고하고 해당 실행의 DB 변경을 롤백하며 이미 저장되어 남을 수 있는 파일을 알리고 기존 파일·객체를 자동 삭제하지 않는다

#### Scenario: 실패 후 다시 초기화
- **WHEN** 앞선 실패로 프리셋 전용 이미지가 저장소에 남은 상태에서 명령을 다시 실행한다
- **THEN** 같은 원본의 기존 이미지를 재사용해 교육을 설정하고 불필요한 파일 복제나 기존 이미지 덮어쓰기를 하지 않는다

### Requirement: 초기 교육의 운영 정보
고정 교육 3개의 프리셋은 코치 출강 운영 방식·일정과 진행 조건을 상담 후 협의한다는 안내·상담 접수 활성 여부를 명시해야 한다(SHALL). 안내는 과제의 접수 정책임을 편집 설명으로 구별하고 확인되지 않은 원본의 가격·정원·지역·모집기간을 확정 정보로 제공하지 않아야 한다(SHALL).

#### Scenario: 빈 DB의 운영 정보 설정
- **WHEN** migration 후 초기 데이터 명령으로 빈 DB를 설정한다
- **THEN** 기존 교육 3개와 이미지가 생성되고 각 교육의 운영 방식·진행 안내·상담 접수 상태가 프리셋과 일치한다

#### Scenario: 편집한 운영 정보의 재실행 보존
- **WHEN** 기존 교육의 운영 방식·진행 안내·상담 접수 상태를 수정한 후 초기 데이터 명령을 다시 실행한다
- **THEN** 수정한 값과 기존 콘텐츠·이미지가 유지되고 중복 교육이 생성되지 않는다

### Requirement: 초기 데이터와 교육 입력 검증의 일치
초기 데이터 명령은 교육 입력과 동일한 운영 방식·목표·추천대상·커리큘럼 검증 계약을 사용해야 한다(SHALL). 프리셋 전체의 콘텐츠 또는 이미지 입력에 오류가 있으면 기존 부분 저장 방지 계약에 따라 DB와 저장소 쓰기를 시작하지 않아야 한다(SHALL).

#### Scenario: 운영 방식 또는 콘텐츠가 잘못된 프리셋
- **WHEN** 프리셋에 정의되지 않은 운영 방식이나 교육 입력 검증에서 거부하는 목표·추천대상·커리큘럼이 있다
- **THEN** 초기화 실패를 식별 가능한 오류로 보고하며 해당 실행으로 교육과 이미지를 생성하지 않는다

#### Scenario: 공통 검증으로 전환한 뒤 저장 실패
- **WHEN** 유효한 프리셋을 저장하는 과정에서 저장소 또는 DB 오류가 발생한다
- **THEN** 기존 DB 롤백·잔여 파일 안내·재실행 시 파일 재사용 계약이 유지된다

### Requirement: 교육별 프리셋 이미지 경로와 재사용
신규 프리셋 이미지 파일은 프리셋에 기록한 교육별 고정 UUIDv7의 32자 hex images 하위 경로와 원본 내용의 SHA256 파일명을 사용해야 한다(SHALL). 기존 교육의 이미지 키는 변경하지 않으며, 초기화 재실행과 실패 후 재실행에서는 같은 원본의 새 규칙 경로에 남은 파일을 재사용해야 한다(SHALL). 저장소가 이름을 조정하면 반환된 이름을 참조해야 한다(SHALL). media_id의 누락·잘못된 형식·UUIDv7이 아닌 값·프리셋 내 중복은 DB·파일 쓰기 전에 거부해야 한다(SHALL).

#### Scenario: 신규 교육의 이미지 저장
- **WHEN** 빈 DB와 저장소에 교육 3개를 초기화한다
- **THEN** 이미지가 각 교육의 images 하위 경로에 SHA256 기반 PNG 파일명으로 저장되고 실제 저장 키가 교육에 연결된다

#### Scenario: 기존 교육과 이미지의 보존
- **WHEN** 기존 형식 경로의 이미지를 참조하는 교육이 있는 상태에서 초기화 명령을 실행한다
- **THEN** 해당 교육의 이미지 키·파일·운영 정보는 보존되고 없는 교육에 필요한 이미지 저장만 새 경로 규칙을 사용한다

#### Scenario: 실패 잔여 파일의 재사용과 재생성
- **WHEN** 앞선 실패로 새 규칙 경로의 이미지가 남아 있거나, 교육 삭제 후 파일 정리가 끝난 상태에서 초기화를 재실행한다
- **THEN** 남아 있는 같은 원본 파일은 재사용하고 정리되어 없는 파일은 다시 생성하며 기존 연결 파일을 덮어쓰지 않는다

### Requirement: 수집 기록과 운영 필드의 분리
source_url·source_image_url·collected_on·editorial_note는 프리셋 JSON에만 보관하고 Education 모델에 저장하지 않아야 한다(SHALL). 초기화는 이 값을 모델 생성 인자에서 제외해야 한다(SHALL).

#### Scenario: 수집 기록이 포함된 프리셋 초기화
- **WHEN** 수집 기록과 교육 운영 필드가 함께 있는 JSON으로 초기화한다
- **THEN** 교육 3개와 이미지는 정상 생성되고 수집 기록은 JSON에 남으며 DB 열에는 존재하지 않는다
